### 核心问题已找到：ESM vs CommonJS
- 项目 `package.json` 有 `"type": "module"`，所以 Vercel serverless functions 必须用 **ESM 格式**

**问题根因：** `failureAlert.to` 配置成了 `telegram:@heartbeat`，系统试图发消息给 Telegram 用户 `@heartbeat`，但该用户名不存在（从未与机器人有过交互），导致 `chat not found` 错误。

**修复方案：** 把所有4个Cron任务的 `failureAlert.to` 改为 `telegram:6810379425`（老板私聊ID），已在09:00完成。

**修复命令：**
```bash
openclaw cron edit <cron-id> --failure-alert-to "telegram:6810379425"
```

### OpenOrigin API Vercel路由问题 — 已修复

**问题根因：** `vercel.json` 的 rewrite 规则将 `/api/*` 指向 `api/index.js`，但 Vercel serverless function 中 `req.url` 仍包含完整路径 `/api/memory`。代码中：
```js
const segments = path.split('/').filter(Boolean)
// segments = ['api', 'memory']
const table = segments[0] // 'api' ← 错误！应该是 'memory'
```

**修复方案：** 解析路径时跳过 `api` 前缀：
```js
const offset = segments[0] === 'api' ? 1 : 0
const table = segments[offset]
```

**验证结果（修复后）：**
- `GET /api/health` → `{"status":"ok","project":"OpenOrigin API"}`
- `GET /api/memory` → `[]`

**生产部署：** https://openorigin.vercel.app 已更新到最新版本。
